# Protocol Amendment 02：全员序列隔离

**协议 ID**：`protocol-amd-02`  
**冻结日期**：2026-10-01  
**状态**：计算协议已实现并冻结；数据准备仍被科学门禁阻断。  
**规范实现**：`02_code/research_protocol_config.py` 中的 `ProtocolSpec` 与 SHA-256 `protocol_digest`。

## 修订原因

`protocol-amd-01` 的贪心代表序列聚类只检查成员与代表序列之间的关系。不同簇的非代表成员仍可能达到或超过 0.40 一致性，因此该方法不能支持“所有跨分区样本零同源泄漏”的声明。历史 `legacy-v1` 使用较短序列长度作分母，在当前开发集上形成一个不可划分的大连通簇。两版历史协议及其摘要保持不变。

## 冻结定义

1. 输入为长度 10–50、天然氨基酸、未修饰的单体肽。相同序列先合并；来源和实验测定继续逐条核验。
2. 对每对序列做全局 Needleman–Wunsch 比对：match `+2`、mismatch `-1`、gap `-2`；输入按字典序定向，最优得分并列时优先对角、再上、再左。
3. 一致性为该固定最优比对中的相同残基列数除以全部比对列数。含 gap 的列计入分母，不计入相同残基数。
4. 所有一致性 `>= 0.40` 的样本对构成无向边；连通分量是不可拆分的分组单位。不因长度比或代表序列比较跳过样本对。五折开发集和独立留出集只能分配整个连通分量。
5. 外部队列须有独立来源和原始实验测定。每条外部序列与所有开发序列比较；原始研究文献与开发队列重合、或任一跨队列一致性 `>= 0.40` 均阻断。
6. 各训练、验证、内部留出和外部评估分区必须满足既定的两类实测标签条件。无法形成有效划分时状态为 `blocked`；不得为了通过门禁调整阈值、丢弃桥接样本或把未测定样本当作阴性。

## 产物与当前结果

准备产物记录协议参数、摘要、原始输入和证据哈希、连通簇成员，以及全部开发与外部样本对的一致性。`03_experiments/prepared/amd02_evidence_clean_20261001` 对 417 条证据通过的开发记录计算了 86,736 对关系，形成 89 个簇，最大簇 318 条。13 条缺实测依据的旧外部记录已排除；外部队列目前为 0，正式训练门禁仍为 `blocked`。

现有 DRAMP 候选的独立重算见 `03_experiments/audits/dramp_amd02_20261001`：10 条候选与 417 条开发记录的 4,170 对比较均留痕，10 条候选各至少有一对达到阈值。该筛查只判断序列隔离，不将候选视为已验证实验队列。

本修订仅规定可复核的评估流程，不预设模型性能、临床安全性或投稿结论。
