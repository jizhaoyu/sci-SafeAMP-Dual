# MIC 当前版本验收入口完善

**目标：** 提供可供脚本与 CI 调用的当前交付检查，清楚区分当前门禁通过与历史检查不兼容。

**范围：** 仅修改未冻结的 `02_code/accept_mic_delivery.py`，新增 `02_code/check_mic_project.py` 及回归测试、使用说明。原协议、状态、来源、模型、交付 ZIP、历史发布器和历史测试保持原样。

**根因：** 旧发布器 `render` 写死 16/23 库存；当前 README 引用 v26 的 17/42。旧文件被受保护清单绑定，直接修改会破坏溯源。另一个确认的问题是验收 CLI 将发布器的 PASS 提示与 JSON 混合写入 stdout，导致 JSON 消费程序无法解析。

## 任务

- [x] 先写 CLI stdout 的失败回归，复现 PASS 提示污染 JSON。
- [x] 将验收 CLI 的诊断输出转入 stderr，stdout 仅输出一个 JSON；验证不改变验收内容。另修复 Windows GBK 与 UTF-8 消费端的编码问题，增加两个实际子进程回归。
- [x] 新增版本化检查命令，重新执行当前状态、来源、五份文档、九模型/51 OOF 与原结果比较检查，不复用旧证书充当实时通过。
- [x] 报告原始科学状态和历史发布器不兼容。`--scope current` 仅验收当前 MIC 交付；默认 `--scope all` 同时要求历史发布器兼容，不兼容时非零退出，禁止声称全项目通过。
- [x] 检查不执行 fit，不重新训练、不修改科学状态；失败提供 JSON 错误和非零退出。
- [x] 回归覆盖 JSON、无覆盖写入、门禁失败、摘要错误、当前与全部范围不同退出码以及禁止拟合。
- [x] 保存新版本检查产物与测试输出，比较既有交付与冻结文件摘要，补齐使用说明。

**完成标准：** 新命令对实际当前交付复核通过，默认全部范围如实因历史兼容缺口失败；旧测试仍明确披露，不新增跳过或自动放行逻辑。
